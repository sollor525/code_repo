# TCP 序列号计算说明

## 三次握手后的状态

```
客户端初始序列号: isn
服务器初始序列号: isn

三次握手完成后:
- 客户端序列号: isn + 1 (SYN占用1个序列号)
- 服务器序列号: isn + 1 (SYN占用1个序列号)
```

## HTTP 通信序列号计算

### 1. HTTP GET 请求
```
客户端 -> 服务器
- 客户端序列号: isn + 1
- 客户端确认号: isn + 1 (确认服务器的SYN)
- 数据长度: get_data_len
```

### 2. HTTP GET 响应
```
服务器 -> 客户端
- 服务器序列号: isn + 1
- 服务器确认号: isn + 1 + get_data_len (确认GET请求)
- 数据长度: response_data_len
```

### 3. HTTP POST 请求
```
客户端 -> 服务器
- 客户端序列号: isn + 1 + get_data_len (更新序列号)
- 客户端确认号: isn + 1 + response_data_len (确认响应)
- 数据长度: post_data_len
```

### 4. HTTP POST 响应
```
服务器 -> 客户端
- 服务器序列号: isn + 1 + response_data_len (更新序列号)
- 服务器确认号: isn + 1 + get_data_len + post_data_len (确认POST请求)
- 数据长度: post_response_data_len
```

## 关键点

1. **序列号递增**: 每次发送数据后，序列号要增加数据长度
2. **确认号**: 确认对方发送的数据，应该是对方序列号 + 数据长度
3. **头部长度**: 以太网(14) + IP(20) + TCP(20) = 54字节
4. **数据长度**: 总包长度 - 54字节头部长度
